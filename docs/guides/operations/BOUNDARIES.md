# 能力边界（BOUNDARIES）

> 这份文档写**做不到什么**和**会在哪里坏**。功能怎么用见各子系统文档；这里只回答「边界在哪、坏了怎么认、怎么恢复」。
> 原则：先把边界说清，再谈能力。

## 1 环境边界

| 维度 | 现状 | 含义 |
| --- | --- | --- |
| 操作系统 | **只有 Windows 经过验证** | 沙箱 ACL、`icacls`、`.bat` 启动器、SnowLuma 都按 Windows 写 |
| DSH | 桌面版 0.2.1-rc.2 实测；0.2.2-rc.1 可装 | 升级后先跑 `node scripts/verify-dsh-020-adaptation.mjs` |
| Node | `>= 22.13.0` | 用顶层 await、`fs.cpSync`、`node:sqlite` |
| SnowLuma | 第三方专有运行时，**不随仓库分发** | 只探测/打开，不安装、不代扫码（EULA §5.4） |
| 网络 | 本机回环 + 出网（QQ / B站 / 搜索） | 控制台与面板只接受回环；出网过 SSRF 校验 |

**不支持**：多用户/多租户、Linux/macOS、把 SnowLuma 打包进发行版。

## 2 能力矩阵

图例：✅ 能做并已验证 · 🟡 能做但有条件 · ❌ 不做（有意） · 🚧 未做

### 2.1 QQ 侧

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 收群/私聊消息、白名单过滤 | ✅ | 白名单为空且 `allowAllWhenEmpty=false` 时**谁都不响应** |
| 发文本/引用回复/分条 | ✅ | 单条 >500 字 → 400；一次最多 8 条；超频 → 429 |
| 发表情包 / 图片 / 动图 | ✅ | 一条消息只能一张表情；图片单条 8MB / 64MP / 5 张 |
| 看合并转发 | ✅ | 只能看（`qq_get_forward_msg`），不能构造转发发出 |
| 拍一拍 | ✅ | 群聊需 targetUserId；有频率限制 |
| agent 提问 / 审批转 QQ | ✅ | 超时按 `questionTimeoutMs` 失效 |
| 主动找主人（目的机制） | ✅ | 安静时段 / 每日上限 / 额度 / 好友关系多重闸门 |
| 主动搭话（二代 proactive） | ✅ | 与目的机制是**两套**独立机制，可分别关 |
| 潜水 / 沉睡前观察 | ✅ | 说「要睡了」之前必须真的等够静默，桥接会校验 |
| 对话收尾 | ✅ | 对方明确在提问/求助时**拒绝**收尾 |

### 2.2 B站 侧

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 看视频、打分、收藏、评论/回复 | ✅ | 受四本账额度、作息窗口、鱼群守则约束 |
| 发动态 / 编辑动态 / 发图 | ✅ | 有额度与间隔；内容过身份闸与脱敏 |
| 分享视频到 QQ | ✅ | 走 B站 分享卡（小程序卡）；文本链接是备用形式 |
| 回私信、直播间监听 | 🟡 | 默认关，需配置；直播间挂了会一直重挂 |
| 一键抓取偏好（读主人的 B站） | 🟡 | 用**独立的只读凭据**文件，绝不用于发评论 |
| 扫码登录 | ✅ | 二维码轮询；cookie 过期要重扫 |
| 风控 / 验证码 | ❌ | 遇到就失败并记录，不会尝试绕过 |

### 2.3 记忆 / 人格 / 额度

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 按人归属的长期记忆（`memory.db`） | ✅ | 每行带 `owner_id`；别人的私事不进公共场合 |
| 重要事实（生日/忌口/过敏/称呼…） | ✅ | 单独存 `fact` 表；三级隐私 `normal/private/secret` |
| 备注名进记忆 | ✅ | `friends.json` 的 `remark` 每天同步成事实（`label=备注名`）；只在跟这个人说话时给 |
| B站 / 好友爱看见闻区 | ✅ | 她自己写 ≤400 字总结（`src/memory-db.js` 写入见闻区时截断）；不进话题分类 |
| 话题切分 | 🟡 | 只切「启用之后的新对话」；旧档案一个字节都不读、不迁 |
| 侧写（每人一句话） | ✅ | 每天 07:00 生成；手改过的不会被自动覆盖 |
| 多角色（人格 + 记忆 + B站 账本整包切换） | ✅ | 切换是整包换，不是只换提示词 |
| 每日额度（QQ / B站 / 其他 / 总额） | ✅ | 80% 每天提醒一次；100% 停唤醒/评论（不硬杀正在进行的回合） |
| token 看板（逐轮/逐群/峰谷） | ✅ | 精度取决于 DSH 投影；价目表可自定义 |

## 3 失败模式与恢复

| 症状 | 最可能的原因 | 怎么认 | 恢复 |
| --- | --- | --- | --- |
| QQ 完全没反应 | 桥接没跑 / SnowLuma 没登录 / 白名单空 | 面板「概览」看桥接与 SnowLuma 状态 | 启动桥接 → 登录 SnowLuma → 填白名单 |
| 桥接起来了但收不到消息 | SnowLuma 的 WS token 与 HTTP token 是两个值 | `state/bridge.log` 找 401 / 连接失败 | 填对 token，或让「端点自愈」跟随 |
| 回复卡在「繁忙」 | DSH 回合没结束 / 会话退役异常 | 面板会话列表看 pending | 重置该会话，或重启桥接 |
| 她只会说话、不调用工具 | MCP server 没挂上 / 工具被守则拦 / 单个开关关了 | 设置页工具开关；DSH 的 MCP 配置 | 重装 preset（`setup-dsh.mjs`）→ 重启 DSH |
| 工具调用 403 | 会话令牌失效 / 模式不允许 / 已暂停 / 额度到 100% | 返回体里的提示 | 按提示逐项放开 |
| 设置页 401 | 没走 DSH 登录态 | 浏览器直接访问插件 API | 从 DSH 界面进 |
| 面板一直显示「桥接不通」 | `consoleToken` 还没生成 | 面板启动日志那一行 | 先跑一次 `首次启动.bat` / `start.bat`，让桥接写出 `state/console-token` |
| B站 什么都不做 | 不在作息窗口 / 额度用尽 / 账号未登录 | 设置页 B站 状态与 `quota.json` | 调窗口/额度；重新扫码 |
| B站 评论失败 | 风控 / 验证码 / 内容被拦 | 工具返回的 code 与 message | 人工处理，程序不绕风控 |
| 记忆库一直是 0 条 | 还没有对话 / 桥接没写缓存 | `memory.db` 的 `cache_msg` 有没有行 | 先聊两句；确认 `memory.cache` 不是 false |
| 记忆库有缓存但没有话题 | 单边发言（只有一方说话） | `cache_msg` 的 `process_state` 是 `held` | 正常：两边都说过话才会成话题；单边 2 小时后降级成零碎或丢弃 |
| 改代码热重载不生效 | 插件引用的是 `src/*.js`，热重载只重载插件自己的文件 | 现象：改了引擎行为没变 | 重启 DSH |
| DSH 升级后全崩 | `app.asar` 补丁被覆盖 / 协议变了 | 工作区列表空、插件不激活 | `verify:adaptation` → `test:audit` |

## 4 安全边界：承诺与不承诺

**承诺**

- 群友**物理上**碰不到本机：仿真会话的工具面是白名单、fail-closed，本地执行能力全部被 `qq-tool-restrict` 拦。
- 发送**必须**命中白名单；没有「管理员例外」这种后门。
- 密钥不落日志、不进回复；配置读给 UI 时脱敏。
- 不可逆删除不做：清理一律先导出到 `memory-trash/` 或 `_backups/`。
- 控制台与面板默认只监听回环。

**不承诺**

- **提示注入的语义层防护不是 100%**：正则能挡「路径 / 凭据 / 联系方式」这类硬模式，挡不住「用隐喻把信息编码出去」。真正的边界是工具面与白名单。
- 你自己把 DSH 或面板暴露到局域网/公网，本程序不负责那层安全。
- 本机已被入侵（同用户权限的恶意进程）时，文件级防护只能提高成本，不能保证。
- B站 / QQ 风控、SnowLuma 的稳定性都不在本程序控制范围内。

## 5 资源边界

| 资源 | 现实量级 | 说明 |
| --- | --- | --- |
| 磁盘（记忆） | `memory.db` 几百 KB 到几十 MB | WAL 模式，另有 `-wal`/`-shm` |
| 磁盘（B站 缓存） | 几十 MB 到数 GB | 视频封面、抽帧、下载的视频 |
| 上下文 | 注入块 2k 字左右 + 未读 + 目的提示词 | 三个旋钮：`role.maxInjectChars`、`context.*`、`promptMaxChars` |
| 请求频率 | QQ 发送 8/分钟、60/小时 | 超限直接拒，模型会改策略 |
| 会话数 | 每个 QQ 会话一个 DSH 会话 | 群多时 DSH 会话数线性增长（可重置回收） |
| 内存 | 桥接常驻数百 MB | `social-v2.json` 启动时全量读 |

## 6 数据出机边界

| 会出机的数据 | 去哪 | 怎么关 |
| --- | --- | --- |
| 群聊文本（拼进提示词） | 模型 API | 关掉对应模式 / 不给白名单 |
| 黑话词条 | 搜索后端 | `slang.autoResearch=false` |
| B站 公开内容（视频/评论） | 模型调用 | 关 `biliBridge.memory.enabled` |

**不会出机**：cookie / 令牌（只在本机文件里）、`config.json`、`state/`、`~/.dsh/stellar/` 里的原始文件。

## 7 必须由人做的事（程序有意不做）

1. 安装/登录 SnowLuma（扫码）。
2. 填主人 QQ 与白名单——程序不替你猜。
3. B站 扫码登录 / 续期。
4. 处理 B站 / QQ 的风控与验证码。
5. DSH 升级后跑体检（`verify:adaptation` / `test:audit`）。
6. 决定什么时候公开仓库（先跑 `node scripts/privacy-scan.mjs --strict`）。

## 8 已知未做 / 结构性问题

| 项 | 性质 | 备注 |
| --- | --- | --- |
| `src/bridge.js` 是两万行的单体 | 架构债 | 拆分要单独一轮 + 完整回归 |
| 两个进程写同一份 `config.json`，无跨进程锁 | 已知风险 | 原子写保证不写坏，极端情况下后写覆盖先写 |
| 面板绑回环仍能被同机其他账户读到明文口令 | 环境限制 | HTTP 请求带不来「哪个 Windows 用户」，应用层修不掉 |
| 记忆库只记「启用之后」的对话 | 设计 | 旧档案不迁，避免把不确定格式的数据混进来 |
