# B站 子系统

> 这份文档回答：B站 这半是「谁」在活动、一天怎么过、每一次对外发言要过几道闸、额度怎么算、坏了会怎么坏。
> 只写现在成立的事实，不引用代码行号（行号会漂）。要改行为，去设置页或 `bili.config.json`。

> 路径简写：`tools/` = `plugins/stellar/tools/`、`lib/` = `plugins/stellar/lib/`、`src/` = 仓库根 `src/`、`~/.dsh/stellar/` = 运行时数据目录。

---

## 0. 一句话

**B站 这半，是同一个角色用另一个账号、另一个作息、另一套额度，在公开互联网上过日子。**

- **谁在活动**：一个 B站 账号，cookie 在 `~/.dsh/stellar/bili/credentials.json`；人格与 QQ 侧共用同一张角色卡。
- **谁在驱动**：插件宿主里的生物钟调度器（`lib/scheduler.js`），每 60 秒一拍，到点往她那条固定 DSH 会话里塞一个回合。
- **和 QQ 的关系**：同一个人，两个世界。共享角色卡与记忆库（`memory.db`），但 B站 侧**绝不出现 QQ 号与群号**。
- **它是公开面**，所以有两套硬约束：管分寸（额度、鱼群保护）、管不泄密（出站身份闸、脱敏）。

## 1. 账号与凭据

### 1.1 两个账号，用途不同

| 角色 | 是谁 | 文件 | 能干什么 |
| --- | --- | --- | --- |
| **她 / self** | 她自己的 B站 号（公开面） | `~/.dsh/stellar/bili/credentials.json` | 看视频、评分、评论、回复、弹幕、发动态、分享、私信主人 |
| **主人 / owner** | 使用者本人 | `~/.dsh/stellar/bili/owner-credentials.json` | 只用于「一键抓取偏好」的只读扫描；**不拿主人号发任何内容** |

`owner.mid` / `owner.name` 决定她要 @ 谁、私信只能发给谁、出站文本里哪些数字被保护。
单账号用户允许 `self.mid === owner.mid`，扫码时需显式勾选「与主人同一个号」。

### 1.2 扫码登录

设置页「B站」页签点扫码 → 本机开 Edge 走手机端 H5 登录 → 回填 cookie 到上面两个文件。用 Edge 是因为 B站 的登录页在无头 Chromium 里常被判风险。

### 1.3 权限边界

B站 那条 DSH 会话默认 `danger-full-access`（`bili.config.json` 的 `agent.sandbox`）。原因很实在：`workspace-write` 下 `%USERPROFILE%` 会因 WRITE_OWNER 起不了命令，定时醒来的她一条 `bili.mjs` 都跑不了。想收紧就改这一项，下一次 tick 生效。

## 2. 生物钟

### 2.1 tick 与五个循环

调度器每 60 秒一拍，按当前时间决定要不要做下面这些事：

| 循环 | 做什么 | 默认触发 |
| --- | --- | --- |
| 醒来刷 | 到窗口就叫醒她，看视频、写日记 | 见 2.2 的窗口 |
| 四类动态提醒 | 到点提醒她发一条动态（游戏/动画/生活/游戏实况轮换） | 各类有独立时段；两条间隔 ≥ `dynamics.gapMin`（默认 30 分钟） |
| 评论区倾听 | 有人回复她、@ 她 → 叫醒 | 间隔 `listen.commentIntervalSec`（默认 300 秒） |
| 空间提醒 | 到点提醒她发 QQ 空间说说；监看主人新说说与她的说说下的新评论 | `qzone.time` 默认 21:30，每天 ≤ `qzone.dailyLimit` 2 条 |
| 日报 / 三连 / 好友爱看 | 写今日日报、给当天最高分视频三连、刷好友爱看 | `report.time` 23:30、`triple.time` 22:30、爱看 20:30 |

### 2.2 作息窗口

`night.windows` 定义每天允许醒来的时段，每个窗口 = 一次机会。出厂：

| 窗口 | 醒来次数 |
| --- | --- |
| 06:00–09:00 | 1 |
| 12:00–14:00 | 1 |
| 18:00–21:00 | 2 |
| 21:00–00:30 | 2 |

另有 `night.maxWakesPerDay`（默认 6，硬上限 3 是单窗口的旧限制）、`skipChance` 0.3（有 30% 概率这一拍跳过）、`minGapMin` 20（两次醒来至少隔 20 分钟）、`videoTargetPerDay` 40（每天目标视频数）、`weeklyMax` 140。

「摸鱼模式」会把这套覆盖成：每天醒来 ≤12 次、目标视频 60 个、最小间隔 15 分钟（见 `lib/run-mode.js` 的 `modeLimits`）。「最低限度运行模式」不叫醒她，只回消息。

### 2.3 会话隔离

B站 侧跑在她自己那条固定 DSH 会话里（`bili-whale` / `bili-whale-<角色id>`），跨天保留上下文，不是每天开新会话；要清就重开会话。这条会话与你的聊天窗口互不影响。

## 3. 会写出去的东西

### 3.1 一条评论要过六道闸（顺序不能换）

1. **能力开关**：`biliComment` 关着就直接不做。
2. **四本账额度**：当天这一类还有没有余量（见第 6 节）。
3. **冷却**：同一 UP、同一视频、同一条评论、任意两条之间。
4. **沉默逛**：`interact.enabled=false` 时只看不说。
5. **鱼群保护**：这一条评论区鱼太多就不发新楼层（见第 7 节）。
6. **出站身份闸**：正文里出现主人/别人的账号或「QQ + 数字」形态，直接拒发（见第 8 节）。

### 3.2 四类动态

游戏、动画、生活、游戏实况四类轮换，每类有自己的时段、长度和开头。先判「够不够格」（今天有没有看够、有没有素材），再判「该不该现在发」（间隔、当天条数）。整块可以用 `dynamics.enabled` 关掉。

### 3.3 分享

有三条载体：把她自己的动态当载体、直接发视频卡片、分享成小程序卡到 QQ。共用一本分享账（`quota.shareDaily` 默认 3 条/天）。

**分享到 QQ 走的是 B站 的分享卡**（`get_mini_app_ark`，`type=bili`），不是贴一条链接。卡片标题恒为「哔哩哔哩」，真标题在 `desc`，真地址在 `qqdocurl`；网传的预览图常 404，要看画面得让她真的去看那条视频。

### 3.4 私信

写死三条：只能发给主人、陌生人只回不发、正文过同一套隐私闸。私信有独立账本（`dm-quota.json`）。

### 3.5 弹幕

`danmaku` 发一条弹幕，长度与内容由 B站 侧限制；`await` 是廉价进程守「有人回我」，命中就退出叫醒她（0 token）。

### 3.6 待审与报备

会写出去的动作里，发动态、发评论、vlog 发布这类默认要过控制台的「待办审批」；只读动作（看空间、看视频、搜索）不打扰你。审批 30 分钟没人处理就作废。

## 4. 只看不写的

| 命令族 | 干什么 |
| --- | --- |
| `feed` / `gamefeed` | 按口味配额选题；候选池 |
| `debrief` / `watch-video` / `subtitles` / `video` | 不点开视频也能知道它讲什么：简介、字幕、弹幕、热评、抽帧 |
| `watch-history` / `likes` / `fav` | 她看过什么、赞过什么、收藏了什么 |
| `comments` / `comment-digest` / `check-reply` | 评论区内容与「谁找过我」 |
| `prefs` / `quota` / `pool` / `cost` | 偏好、额度余量、素材池、花费 |
| `my` / `whois` / `session` | 账号信息、认人、凭据状态 |

全部子命令用 `node bili.mjs` 不带参数列出来（当前 59 条）。

### 4.1 看视频：先看目录，再问细节

`watch` 不再把字幕全文摊进上下文，只回一份 **5 分钟目录 + 字幕覆盖率**；要先看「这片子讲了什么」看目录通常就够。

要具体细节用 `find`（`stellar_bili_find`）：只回 2~3 段带时间戳的原文，并一定附「字幕覆盖到哪一段」。
索引来自 `debrief`（`shots/` 里存分段字幕摘要，`shots.retentionDays` 过期后会提示重新 debrief）；
`watch` 自己也会建索引，所以第一次 `find` 不必先跑 `debrief`。
**字幕全文只落盘、不进上下文** —— 想读全文是 `read` 一个文件，不是把整条字幕塞进对话。

## 5. 记忆与打分

### 5.1 三个账本

**打分账**（看过哪些、打几分）、**观看账**（看了多久、抽了几帧）、**发言账**（说了什么、在哪儿说的）。三个都落在角色目录的 `bili/` 下，按本地日切。

### 5.2 B站 见闻区

她每刷完一轮，会往记忆库的**见闻区**写一段 ≤400 字的总结（`zone_note` 表，`zone=bili`），可以带 `items`（BV 号列表）。被问「你今天在 B站 看了什么」时**先查这个区**，不要拿聊天记忆凑。

见闻区不按话题分类，就是她自己写的流水总结；面板「记忆」页有专门的卡片可以看和删。

### 5.3 日记

`diary` 写 `characters/<角色>/bili/whale-diary.md`（叙事）与 `whale-log.jsonl`（结构化）。面板「记日记」统计的是后者。

## 6. 额度

### 6.1 四本账（可配置，代码不信配置文件、越界会夹回范围）

| 键 | 含义 | 默认 | 范围 |
| --- | --- | --- | --- |
| `limits.daily` | 普通评论 / 天 | 30 | 0–200 |
| `limits.replyDaily` | 回找我的人 / 天 | 50 | 0–500 |
| `limits.taDaily` | 主动搭话 / 天 | 15 | 0–200 |
| `limits.mineDaily` | 动态回复 / 类 / 天 | 10 | 0–100 |
| `limits.minePerPerson` | 动态回复 / 人 / 类 / 天 | 1 | 0–20 |
| `limits.perUpMin` | 同一 UP 冷却（分钟） | 10 | 0–1440 |
| `limits.perVideoMin` | 同一视频冷却（分钟） | 60 | 0–1440 |
| `limits.perThreadMin` | 同一条评论冷却（分钟） | 1440 | 0–10080 |
| `limits.globalMin` | 任意两条发言间隔（分钟） | 2 | 0–120 |

0 = 不限制。**这些是防刷屏的硬上限，不是建议值**；改大之前先想清楚 B站 风控。

### 6.2 另外三本

- **分享账**：`quota.shareDaily` 默认 3 条/天，外加 7 天判重与沉默衰减（`share.silentAfterDays` 3 天、`share.decayPerDay` 1）。
- **私信账**：`dm-quota.json`，独立计数。
- **生成图额度**：每天 3 张（与 QQ 侧同一本账）。

### 6.3 超限与损坏时

一律 fail-closed：账本读不出来就当额度用尽，宁可少说一句，不冒着刷屏风险硬发。

## 7. 鱼群保护

### 7.1 解决什么

同一批人（「鱼」）在评论区刷屏时，她再挤进去只会显得像同类机器人。保护的做法是：鱼太多就不发新楼层，改为优先回鱼、给鱼点赞。

### 7.2 怎么认鱼

三种方式任一命中：**开头词** `namePrefixes`、**结尾词** `nameSuffixes`、**中间包含** `nameContains`，另外可加 `extraFishMids` 白名单。

**出厂全部为空 = 不做同类识别。** 这是刻意的：宁可不动，也不误伤真人。想让它在你的圈子里生效，把你自己那套人格名填进 `nameSuffixes`。

### 7.3 阈值

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `sampleSize` | 40 | 只看最近多少条顶层评论 |
| `maxFishTopLevel` | 3 | 鱼顶层评论达到 N 条就不发新楼层 |
| `maxFishMids` | 3 | 不同鱼账号数阈值（防同一只鱼刷楼） |
| `maxFishRatio` | 0.4 | 鱼占比阈值 |
| `minSample` | 8 | 样本太少不判定 |
| `forceGather` | true | 每次醒来都强制聚拢并主动评论一次 |
| `maxLikesPerDay` / `maxLikesPerRun` | 6 / 4 | 点赞上限，避免像刷赞 |

点赞之间随机间隔 1.5–4 秒，发完评论先等 12 秒再点赞（同一条视频里「刚发完就点赞」很像脚本）。遇到 -509/12015/12051 这类风控码，熔断 60 分钟。

## 8. 出站身份闸

B站 评论与动态是公开面，一旦把主人的 QQ 号、主人的 B站 mid、或对齐表里别人的账号贴出去，就收不回来。所以这层是**正则硬拦**，不是提示词里的「不许泄露」。

受保护：`admin.qq`、`admin.biliMid`、`owner.mid`、`alignments.json` 里每个 link 的各平台 id，以及任何「QQ / 群号 + 数字」形态（即使不在名单里，那也是在往外递联系方式）。

**明确不拦**：她自己的 B站 mid（公开资料）、昵称（会撞、误伤成本高）、普通数字。

这一层只决定「要不要发」，不改写内容。提示词侧还有一层脱敏，但那是概率约束，不能当保证。

## 9. 配置（`bili.config.json`）

主要几段：`persona`（称呼与自称）、`preferences`（喜欢/不喜欢与权重）、`owner`（主人 mid 与昵称）、`limits`（四本账）、`dynamics`（四类动态）、`qzone`（空间说说与监看）、`report` / `triple` / `vlog`（每日固定动作）、`share`（分享开关与阈值）、`listen`（评论区与直播倾听）、`night`（作息窗口）、`capabilities`（能力开关）、`fishGuard`（鱼群保护）、`agent`（会话权限）、`shots`（视频缓存）。

设置页改的是这份；**合体层的 `~/.dsh/stellar/config.json` 是另一份**（桥接与插件读），两份都要写时用面板的「设置」页，它会双写。

## 10. 失败模式

| 现象 | 先看什么 |
| --- | --- |
| 一条命令都不跑 | `agent.sandbox` 是不是被收紧成 `workspace-write` |
| 登录过期 / cookie 失效 | `node bili.mjs session`；重扫码 |
| 风控 / 限流 | 日志里的 `-509` / `12015` / `12051`；等熔断，别改大额度硬撞 |
| 空间监看报「响应结构异常」 | 上游偶发或限流，不是本地配置问题；过一会儿自己好 |
| 数据文件损坏 | 额度账本损坏 = 当作额度用尽（fail-closed）；删对应账本会重置计数 |
| 她一直不醒 | 运行模式是不是「最低限度」；`night.windows` 是不是被改空 |
